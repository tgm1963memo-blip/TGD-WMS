# Seed Data Foundation Documentation

## Purpose
Provide a deterministic, **fake/demo** data set that can be loaded into a **staging** Supabase instance for testing the TGD WMS application. The data is only a **foundation** – it does not contain any real customer, employee, or production information.

## **DO NOT execute against production**

## Seed Data Principles
- **Deterministic IDs** – UUIDs are hard‑coded so tests can reference them reliably.
- **Demo‑only** – All emails, names, and identifiers are clearly marked as demo (e.g., `admin.demo@tgd-wms.local`).
- **No real Supabase keys** – The seed files never contain a Supabase URL, service‑role key, or any authentication secret.
- **Isolated by Customer** – Data for each `customer_id` is kept separate; the same product can appear under multiple customers with independent quantities.
- **Supports Role Mapping** – Includes rows in `tgd_user_profiles` for every WMS role (admin, warehouse_manager, warehouse_staff, accounting, viewer).
- **Supports Future Tests** – Provides enough rows for stock‑movement, balance, accounting‑charge preview, and RLS isolation scenarios.
